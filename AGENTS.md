# AGENTS.md — заметки для агента, дорабатывающего этот репозиторий

Ориентир для будущих сессий. Не дублирует README — фиксирует неочевидное: устройство, конвенции,
гочи, как проверять. Держись этого при доработке.

## Что это

`yougile-skill` — распространяемый **скилл для ИИ-агентов**: работа с трекером задач YouGile через
REST API v2. Ставится пользователям через `npx skills add AleshaIdetRvat/yougile-skill`. Этот
git-репозиторий — источник правды; «релиз» = `git push`.

## Критическая раскладка (не сломай)

Сам скилл живёт в подпапке **`yougile/`**, а не в корне репозитория. Причина: `npx skills` считает
корневой `SKILL.md` «однофайловым скиллом» и копирует **только** его, теряя `scripts/` и
`references/`. **Не переноси `SKILL.md` в корень.**

## Карта репозитория

- `README.md` — **русский**, для владельца: установка, доступ, что выяснилось на живом аккаунте.
- `AGENTS.md` — этот файл. `CLAUDE.md` просто импортирует его.
- `yougile/SKILL.md` — **английский**, для агента-потребителя. Тонкий (~100 строк): проверка ключа,
  команды, правила «на каждый вызов», таблица «куда смотреть дальше». Фронтматтер `description` —
  триггер, по нему агент решает, брать ли скилл вообще.
- `yougile/ABOUT.md` — английский, для человека с вопросом «что это».
- `yougile/references/auth.md` — онбординг (логин+пароль / готовый ключ), хранение ключа, права.
- `yougile/references/recipes.md` — сценарии и поведение, на котором легко обжечься.
- `yougile/references/api.md` — эндпоинты, формы полей, коды ошибок.
- `yougile/scripts/yougile.py` — CLI. **Только stdlib**, Python 3.8+. stdout — всегда JSON,
  ошибки — в stderr с ненулевым кодом. Коды: `2` HTTP-ошибка / `3` нет ключа или пароля /
  `4` ключ отвергнут / `5` нужен выбор компании / `6` сеть.

## Конвенции

- **Язык.** `SKILL.md`, `ABOUT.md`, `references/`, скрипт и все его сообщения — по-английски.
  `README.md` и этот файл — по-русски. Исключение: готовые реплики пользователю внутри
  `auth.md` — на русском, они цитируются агентом дословно.
- **Коммиты.** Conventional Commits на русском. В окружении владельца есть скилл `/git-commit`.
  История без Claude-трейлеров — не добавляй их.
- **Скрипт.** Никаких зависимостей сверх stdlib — это главное обещание скилла. Новую
  функциональность добавляй подкомандой, а не отдельным файлом.
- **Утверждения о поведении API проверяй запросом**, а не доверием к доке YouGile: она в
  нескольких местах расходится с реальностью (см. ниже).

## Философия

- **Тонкий SKILL.md, прогрессивное раскрытие.** В `SKILL.md` — только то, что нужно почти всегда.
  Всё остальное в `references/`, куда `SKILL.md` отправляет таблицей в конце. Раздувать его —
  значит платить контекстом на каждом запуске.
- **Скрипт печатает действенные ошибки.** У `ApiError` есть подсказки под 400/401/403/404/429 —
  агент должен понять, что делать, не читая доку.
- **Не отказывать заранее.** Скилл не должен посылать пользователя к админу или говорить «задачи
  нет», пока это не проверено: и то и другое было ложным.

## Гочи API (проверено на живом аккаунте, а не взято из доки)

- **Пагинация по `offset` теряет строки.** Колонка из 41 задачи, страницы по 5/10/20 → одна строка
  дублируется, другая пропадает; страницы идут задом наперёд. `paginate()` поэтому берёт одну
  страницу на 1000 (максимум сервера) и дедуплицирует по `id`. Не «оптимизируй» обратно.
- **`/auth/keys/get` отдаёт голый массив**, а не `{"content": [...]}`. И он пер-юзерный — чужие
  ключи не видны.
- **Ключ может выпустить любой сотрудник**, не только админ; ключ несёт права владельца.
- **Отказ по правам — это `400` («Not enough permissions», «Не удалось создать колонку») или
  `404`**, а не `403`. `403` встретился только на `PUT /users/{id}`.
- **`PUT`: `stickers` сливается, массивы (`subtasks`, `checklists`, `assigned`) замещаются.**
- **`columnId` не обязателен** в `POST /tasks`; задача без него — настоящая подзадача.
  `parentId` не существует, обнулить `columnId` потом нельзя.
- **`completed: true` переносит задачу** в финальную колонку доски.
- **`archived: true` не прячет** задачу из `GET /tasks`; прячет только `deleted`.
- **Стикеры:** только `/string-stickers` и `/sprint-stickers`; значение — id состояния, не текст;
  снять — `""` или `null`. Бейджи других типов из UI через API недоступны совсем (404).
- **Цвета задачи:** `task-red|yellow|green|turquoise|blue|violet|pink|gray|primary`. `task-orange`
  нет; снять цвет нельзя (`null`/`""`/`task-none` → 400).
- **Порядок:** новая колонка встаёт крайней слева, поля `position/order/index` нет нигде.
- **Время** — epoch ms, приложение рисует в локальной зоне зрителя (полночь UTC → «03:00» в МСК).
- **Лимит ~50 запросов/мин** на компанию; 429 ретраится с бэкоффом внутри `call()`.
- **Комментарий: разметка только в `textHtml`.** HTML в `text` приложение показывает как есть,
  сырыми тегами (15.09.2026, четыре комментария подряд). Отсюда флаг `--html` у `tasks comment`.
  Отправленное сообщение не редактируется: `PUT` отвергает `text` и `textHtml`, принимает
  `deleted` — чинить переотправкой.
- **`tasks create` не заводит подзадачу:** обёртка шлёт `columnId: null`, YouGile отвечает 400.
  Подзадачу создавать сырым `request POST /tasks` без `columnId` (проверено 11.09.2026).

## Как проверять изменения (реально запускать, не только читать)

```bash
python3 -m py_compile yougile/scripts/yougile.py
python3 yougile/scripts/yougile.py status                      # ключ жив?
python3 yougile/scripts/yougile.py projects list --all
python3 yougile/scripts/yougile.py tasks list --title "тест" --limit 5
```

Для сквозной проверки заведи временную доску, погоняй на ней create/update/move/comment и удали
за собой (`--deleted true`). Не тестируй на чужих боевых проектах.
