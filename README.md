# yougile — трекер задач YouGile для ИИ-агентов

Скилл даёт агенту работать с досками [YouGile](https://ru.yougile.com) через REST API v2:
найти задачу, создать, отредактировать, перетащить между колонками, прокомментировать, поставить
дедлайн и бейджи, разложить проект по доскам и колонкам.

| Чтобы дать агенту доступ к YouGile, обычно нужно… | …здесь |
|---|---|
| 🔑 разобраться, где выпускать API-ключ, и не быть ли для этого админом | скилл сам проведёт по шагам |
| 📋 руками достать `companyId`, потом ключ, потом сохранить его | одна команда `login` |
| 📚 читать доку и выяснять, что `PUT` затирает массивы | всё описано в `references/` |
| 🐍 ставить SDK и зависимости | ничего, только `python3` |
| **итого действий:** | **поставить скилл и назвать логин с паролем** |

> Этот README — на русском для удобства владельца. Сам скилл (`SKILL.md`, `ABOUT.md`, скрипт)
> — на английском.

## Установка

### Проще всего — попросить ИИ-агента

Скиньте своему агенту (Claude Code, Codex, Cursor — любому) вот эту строчку:

> Установи мне скилл https://github.com/AleshaIdetRvat/yougile-skill — открой README
> и следуй разделу «Инструкция для ИИ-агента».

Дальше он разберётся сам: определит, куда класть, поставит и проверит. Ничего знать заранее не
нужно.

### Инструкция для ИИ-агента

*Ты читаешь это, потому что пользователь попросил установить скилл по ссылке. Выполни шаги ниже и
отчитайся. Скилл — это папка `yougile/` из этого репозитория.*

**Шаг 1. Определи целевую папку** — по тому, в каком агенте ты работаешь:

| Агент | Глобально (все проекты) | Только текущий проект |
|---|---|---|
| Claude Code | `~/.claude/skills/` | `./.claude/skills/` |
| Codex | `~/.codex/skills/` | `./.agents/skills/` |
| Cursor | `~/.cursor/skills/` | `./.agents/skills/` |
| OpenCode | `~/.config/opencode/skills/` | `./.agents/skills/` |
| другой | `~/.agents/skills/` | `./.agents/skills/` |

Если пользователь не сказал иначе — ставь глобально.

**Шаг 2. Основной путь — установщик `npx skills`.** Проверь, есть ли `npx` (`command -v npx`).
Если есть:

```bash
npx -y skills add AleshaIdetRvat/yougile-skill -g -y
```

Он сам определит агента и разложит файлы. Флаг `-g` убери, если ставишь только в текущий проект.
Можно указать агента явно: `-a claude-code`, `-a codex`, `-a cursor`.

**Шаг 3. Если `npx`/`node` нет — поставь вручную** (нужен только `git`). Подставь путь из шага 1:

```bash
DEST="$HOME/.claude/skills"        # ← путь из таблицы в шаге 1
git clone --depth 1 https://github.com/AleshaIdetRvat/yougile-skill /tmp/yougile-skill
mkdir -p "$DEST"
rm -rf "$DEST/yougile"
cp -r /tmp/yougile-skill/yougile "$DEST/yougile"
rm -rf /tmp/yougile-skill
```

Копируй именно подпапку `yougile/`, а не весь репозиторий: в целевой папке должно получиться
`yougile/SKILL.md`, `yougile/scripts/`, `yougile/references/`.

**Шаг 4. Проверь, что всё встало:**

```bash
python3 "$DEST/yougile/scripts/yougile.py" status
```

Успех — если в ответ пришёл **любой JSON** с полем `hasKey`: значит файлы на месте и `python3`
рабочий. На чистой машине там будет `"hasKey": false` и подсказка про онбординг — это нормально,
ключа ещё нет. Если же вылетела ошибка Python или файл не найден — установка не удалась. Если нет
самого `python3`, скажи пользователю, что нужен Python 3.8+; других зависимостей у скилла нет.

**Шаг 5. Отчитайся пользователю** — коротко:

- скилл установлен, назови папку;
- сессию агента надо перезапустить, иначе скилл не подхватится;
- при первом обращении к YouGile скилл попросит доступ (логин с паролем или готовый API-ключ),
  права администратора для этого не нужны.

**Чего делать не надо:** не запускай `login`/`setup` и не спрашивай пароль от YouGile на этапе
установки — скилл сам проведёт по онбордингу, когда пользователь поставит первую реальную задачу.

### Обновление и удаление

```bash
npx skills update            # обновить до свежей версии из репозитория
npx skills remove yougile    # удалить
npx skills list              # посмотреть, что установлено
```

Если ставили вручную — обновление это тот же `git clone` + `cp -r` из шага 3, он перезаписывает
папку.

## Первый запуск: доступ

Агент один раз попросит доступ и предложит два пути:

1. **Логин и пароль** — агент сам получит API-ключ: покажет список компаний, спросит нужную,
   создаст ключ и сохранит **только его**. Пароль никуда не записывается.
2. **Готовый ключ** — если пароль отдавать не хочется: YouGile → `Ctrl + ~` (или ⚙️ на странице
   проектов) → настройки API → создать ключ → прислать агенту.

**Права администратора не нужны** — обычный сотрудник тоже может выпустить ключ (проверено). Ключ
работает от имени владельца и открывает ровно то, что видит сам человек: чужие проекты для него
просто не существуют (404). Хранится в `~/.yougile/credentials.json` (права 600) на машине
пользователя, у каждого свой — ничем делиться не нужно.

Отозвать ключ: `python3 scripts/yougile.py request DELETE /auth/keys/<key>`,
забыть локально: `python3 scripts/yougile.py forget`.

## Что внутри

```
yougile-skill/                   # репозиторий
├── README.md                    # этот файл — лендинг репо
├── AGENTS.md                    # заметки для агента, который дорабатывает репо
└── yougile/                     # САМ СКИЛЛ — это и копирует `npx skills`
    ├── SKILL.md                 # тонкая инструкция агенту: проверка ключа, команды, правила
    ├── ABOUT.md                 # что это и как устроено — для человека
    ├── references/
    │   ├── auth.md              # доступ, хранение ключа, что делать при нехватке прав
    │   ├── recipes.md           # сценарии + поведение, на котором легко обжечься
    │   └── api.md               # эндпоинты, формы полей, коды ошибок
    └── scripts/
        └── yougile.py           # CLI над API: только stdlib, вывод — всегда JSON
```

> Почему скилл лежит в подпапке, а не в корне репо: установщик `npx skills` считает `SKILL.md` в
> корне «однофайловым скиллом» и копирует **только** его, теряя `scripts/` и `references/`.
> Скилл в именованной подпапке копируется целиком.

Философия: `SKILL.md` тонкий (~100 строк) и содержит только то, что нужно почти всегда. Детали
подтягиваются из `references/` по мере надобности — контекст агента не забивается на старте.

## Команды скрипта

```bash
python3 scripts/yougile.py status                       # работает ли ключ
python3 scripts/yougile.py login --login me@x.ru --password-stdin
python3 scripts/yougile.py projects list --all
python3 scripts/yougile.py boards  list --project-id <id> --all
python3 scripts/yougile.py columns list --board-id <id> --all
python3 scripts/yougile.py tasks   list --title "деплой"
python3 scripts/yougile.py tasks   get  --id SAI-515     # можно по коду задачи
python3 scripts/yougile.py tasks   create --title "..." --column-id <id> --assigned <userId>
python3 scripts/yougile.py tasks   move --id <id> --column-id <id>
python3 scripts/yougile.py tasks   comment --id <id> --text "Готово"
python3 scripts/yougile.py request GET /string-stickers --query limit=100   # сырой доступ к любому эндпоинту
```

Все команды принимают `--key` и `--base-url`. Для коробочной версии:
`setup --base-url https://<домен>/api-v2`.

## Что выяснилось на живом аккаунте

Это не пересказ документации — всё проверено запросами и сверено с тем, что рисует приложение.
Из-за таких мелочей агент обычно и портит данные:

- **`PUT` ведёт себя по-разному для разных полей.** Объект `stickers` сливается по ключам, а
  массивы `subtasks`, `checklists`, `assigned` **замещаются целиком** — отправил один чеклист,
  остальные удалились. Читать → дополнять → отправлять целиком.
- **Пагинация по `offset` ломается**: обход колонки из 41 задачи страницами по 5/10/20 стабильно
  возвращает одну строку дважды и **теряет** другую. Скрипт поэтому берёт одну страницу на 1000.
- **`archived: true` не прячет задачу** из выдачи API — фильтровать надо самому. Прячет только
  `deleted`.
- **Отказ по правам приходит как `400` или `404`**, а не `403`. `404` на задачу часто значит «нет
  доступа», а не «не существует» — нельзя говорить пользователю, что задачи нет.
- **`complete` не только ставит галочку, но и переносит** задачу в финальную колонку доски.
- **Подзадача — это задача без `columnId`** (он не обязателен при создании, вопреки доке).
  Если привязать задачу с колонкой, она останется ещё и карточкой на доске.
- **Колонка, созданная через API, встаёт крайней слева**, а поля позиции нет — создавать надо в
  обратном порядке.
- **У стикера можно выставить только id состояния**, свободный текст отвергается. И не все типы
  бейджей вообще доступны: в API v2 живут только `string-stickers` и `sprint-stickers`.
- **Цветов ровно 9** (`task-orange` не существует), и снять цвет с задачи нельзя никак.
- **Лимит ~50 запросов в минуту** на компанию — работать последовательно, не веером.
- **Упомянуть человека через API нельзя.** Настоящее упоминание из приложения хранится отдельной
  отметкой с id пользователя, а API эту отметку не принимает: `@Имя` в тексте комментария остаётся
  просто текстом, без подсветки и уведомления. Отметить человека — только руками в приложении.

Подробности и готовые рецепты — в `yougile/references/`.

## Требования

`python3` (3.8+) и сеть до YouGile. Ни pip-пакетов, ни Docker, ни привязки к конкретному агенту:
скилл — это markdown плюс один stdlib-скрипт, поэтому работает у всех, кто умеет запускать
shell-команду. Агенту без shell хватит `references/api.md`, чтобы ходить обычными HTTP-запросами
с заголовком `Authorization: Bearer <key>`.
